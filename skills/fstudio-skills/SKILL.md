# Fstudio_skills

把工艺语义、设计意图和原生运行行为一起交付。适用于不同设备、分辨率、行业与页面结构；不内置具体项目的罐体、菜单、颜色、寄存器或工程路径。

## 先选工作范围

- 新工程：先核对控制逻辑和设备能力，再用一页代表性页面完成设计到运行的闭环，稳定后推广。
- 原型还原：原型是视觉依据，点表是数据依据，控制程序是状态与动作依据；三者冲突时标明差异，不能默默改成自己的设计。
- 已有工程修复：先复现指定问题，只检查相关控件、共享层及运行结果，不强迫重新设计全工程。
- 仅原型任务：交付原型即可，不擅自加入 PLC 写入、下载或投运。

## 工作起点

1. 读取实际工程、用户指定程序和现有约定，确认文件存在。识别 FStudio 版本、目标型号、原生分辨率、色深、通信设备和工程目录限制。缺项先从项目读取，不凭型号印象填入。
2. 明确本轮可观察的成功条件：例如公共菜单只定义一次、参数可打开键盘、长文本不裁切、某状态正确高亮。区分设计交付、离线验收和硬件验收。
3. 按功能发现工具与接口，做一个只读连接检查。MCP 连通、宿主连通、工程打开是三个不同状态。连接正常且有当前页时优先 `fstudio_canvas_snapshot`，一次取得页面身份、尺寸、控件名称和句柄。不要凭工具列表或进程存在认定可用。
4. 将过程脚本、截图、临时工程、备份和记录集中到一个任务目录。正式工程另存于明确的交付位置；不把临时材料散落进源码目录。

## 工艺到页面

建立最小的数据与动作清单：变量含义、控制器地址基准、设备/站号、类型与字宽、符号、比例、小数位、单位、读写方向、上下限和生效条件。多字数据另外核对字序、字节序。

页面由操作任务决定，不预设所有项目必须有五个菜单。先确定操作员需要观察什么、何时输入、如何知道动作被接受、异常后如何恢复。命令、反馈与阶段状态分别建模；不能拿“按钮按下”当“设备运行”。

视觉与控件设计时读取 [references/design-and-components.md](references/design-and-components.md)。

## 设计到原生工程

1. 获取用户认可的参考版本与关键页面截图，记录节点/版本及画布尺寸。使用 Figma 时遵循宿主提供的 Figma 技能；不可连接时不声称读取了最新设计。
2. 提取颜色、字号、间距、边框、圆角和内容区域。标注公共层与各页专属内容，建立控件与原型的对应关系。
3. 优先实现原生文字、数值、输入、状态指示、菜单动作、报警和趋势。必要的设备插画才作为透明素材导入。动态读数不能烘焙进图片。
4. 先做一页包含共用栏、文本、数字、输入和状态的代表性页面，保存、重开、编译、模拟。测量原生回读尺寸后再批量生成同类组件。
5. 用稳定的业务标识定位组件。先按名称确认唯一匹配，存在则增量修改，缺失才创建，重名先定位原因。`canvas_create_many` 仅创建，不能把它当 upsert 重跑；不要靠列表顺序或过期句柄识别对象。
6. 在目标运行环境检查实际画面和交互。未达到要求时按可见差异修复，不以连续生成更多版本代替定位。

原生接口、序列化、异步与已知陷阱见 [references/fstudio-native.md](references/fstudio-native.md)。只读取当前问题相关章节。

## MCP 执行入口

实际制作或修改前读取 [references/mcp-workflow.md](references/mcp-workflow.md)，按任务选工具，不把全工具目录或模型对象树读进上下文。

| 当前工作 | 优先调用 | 结果用途 |
| --- | --- | --- |
| 接续已有页、找对象、取位置 | `canvas_snapshot`，可按名称筛选 | 获取本会话唯一对象与实际布局 |
| 核对已知的格式、字体、地址路径 | `model_get_many` | 一次取得必要字段 |
| 多对象应用相同宽度/颜色等 | `model_apply_many` | 一组共用属性、一个事务 |
| 多对象应用不同位置或参数 | `model_set_many` | 差异属性集中提交 |
| 创建已验证的控件 | `canvas_create_many` + `presets` | 一次配置和插入，检查 `bounds_adjusted` |
| 初次探索特殊控件 | `canvas_prepare` → 按需发现/配置 → `canvas_commit` | 单实例验证后才推广，废弃草稿需丢弃 |

上表省略 `fstudio_` 前缀；以当前连接 schema 为准。新工具不存在时按参考中的兼容流程退回已有接口，不反复调用不存在的工具。宿主 DLL 未加载新版与工程内容错误分别处理。

## 验收与交付

按照 [references/acceptance.md](references/acceptance.md) 选择与本轮修改匹配的检查，保留每项证据及范围。将“已保存”“已重开”“已编译”“已模拟”“已联机”分别表述，不互相替代。

视觉差异优先修复：错误/缺失内容 → 遮挡与层级 → 尺寸/坐标 → 字体/对齐 → 状态反馈 → 装饰细节。修复布局后必须重新检查邻接对象和公共层影响到的页面。

需要批量检查时，使用 [scripts/check_layout.py](scripts/check_layout.py) 对完整 `canvas_snapshot` 与显式布局约束作只读比较；用法见 [references/mcp-workflow.md](references/mcp-workflow.md)。它检查尺寸、对齐、间距和公共组件禁入名单，不能替代截图、键盘输入或跨页模拟验收。

通过任务要求后交付工程路径、实际验证结果及剩余限制。需要投运、PLC 写入、下载、外部发布时按现有授权边界执行，不能把“制作界面”自动解释成这些动作的授权。

## 提速原则

- 一次发现模型能力，复用当前版本已确认的属性和模板；只有工具版本或配置模式变化时再探索。工程重开后用稳定名称重新获取会话引用。
- 批量处理独立只读操作；有关联的配置、提交、保存、编译按依赖顺序进行。
- 同类控件先验证一个完整实例，再参数化复制；不要先生成几十个再发现全部无法编译。
- 相同失败无新证据时停止重复提交。缩减到最小复现，再分别验证模型、序列化、编译或运行的哪一层失败。
- 视觉模板复用设计规则，不能复用未经确认的设备地址、动作权限或工艺假设。
- 背景、顶栏、菜单先确定唯一所有者，再生成各页内容。几何快照只含当前页自身控件，不能根据子页里没有菜单就判定公共菜单未显示。
- 原生字体、位数和单位布局按实际回读修正；把重复发现的路径、样式预设和已验证约束保存在当前任务资料中，不在每一轮重新研究。
- 不为了看起来像原型而伪造正常通信、运行、液位或报警解除状态。
