# 调用排障

按最先失败的层定位，避免通过反复写工程试探连接问题。

| 现象 | 先核对 | 下一步 |
| --- | --- | --- |
| 技能已加载但没有工具 | 客户端是否注册了实际MCP包，启动入口是否存在 | 按 [bundled-mcp.md](bundled-mcp.md) 定位实际包与连接 |
| 服务列出工具，宿主报未知操作 | Python服务与运行DLL的版本、加载位置及新增能力 | 保存后正常加载匹配宿主，再刷新schema；文件时间戳不是加载证据 |
| 连接成功但没有工程/画布 | 宿主插件是否加载、工作区是否一致、目标工程是否打开 | 做只读状态和画布检查，不修改工程内容解决连接问题 |
| 返回任务ID、等待超时 | 原任务是否仍排队、运行或已完成 | 查询同一个任务ID恢复结果，不重发创建、提交或编译 |
| 句柄失效、对象不属于活动页 | 工程是否重开、活动页是否被其他客户端切换 | 重新发现句柄；协调回草稿原页后释放，先完成当前操作再切页 |
| 属性路径不存在或子对象为空 | 实际模型公开getter与DTO是否混用、当前模式是否初始化该对象 | 按需inspect相关节点，使用已支持的原生工厂/初始化器 |
| 回读成功但编译失败 | 保存快照、寄存器身份、类型/范围、完整子对象及具体错误 | 缩为一个原生样本，保存重开、编译再验证 |
| 编译成功但画面/数据不对 | 模拟器是否加载新产物、原始值、倍率、小数位、alpha及层级 | 用隔离测试值和实际截图对照，不能只改更多样式掩盖问题 |

## 异步与未知结果

每次变更记录当前工程、页面、工具参数和返回的任务ID。调用返回排队/运行状态后，等待该任务到终态；编译等操作的终态还需读取其具体成功字段和错误。工具schema给出的状态入口和字段才是依据，不凭旧版本名称推测新接口。

超时只是客户端未取得结果，不是执行失败。先查原任务；若状态入口失效，恢复连接后按稳定控件名、UUID、数量或产物来源确认结果。尚不能确定是否已提交时，不再次插入或删除同名对象。得到明确失败且已回滚的证据后，才修正原因并重试。一次重试不应扩大原任务范围。

`fstudio_visible_start` 返回 `starting` 只表示已经创建宿主进程。先继续查询只读 `fstudio_visible_state`，若它又返回任务ID，则通过 `fstudio_visible_job` 续查同一任务到完成，再打开工程；不能立即假定宿主已就绪，也不能重复启动另一个实例。前提是这些入口出现在当前连接的schema中。

## 复用编译产物与离线预览

先核对当前连接实际提供的入口。`fstudio_simulate_offline` 保存当前工程，再请求厂商的原生离线模拟服务；它可能触发原生编译或对话框。GUI中的离线菜单是否可执行、后台服务能否解析原生依赖，以及模拟器窗口是否真正显示工程，是不同的状态。后台入口对已验证版本的依赖初始化不代表所有安装都支持；失败时保留具体错误，按当前安装的原生入口人工处理，不用任意反射调用或单独启动FSGUI来绕过。

当前连接具备 `fstudio_simulate_compiled` 时，可传入成功隔离编译的 `build_id`，复用当前已保存工程的产物。入口会重新比对完整源码清单、归档输出哈希和工程身份，拒绝未保存页面、其他工程、既有模拟器及输出目录重解析点。重开工程可能改变原生系统数据库，即使界面未编辑也需重新编译；不要放宽清单检查或仅相信旧的 `source_unchanged`。

该入口使用官方 FCS/FSGUI 的 `SimPlc` 参数，保留 `temp` 记录，不调用“清除记录”对话框。它覆盖本次清单中的生成输出，保留其他生成文件；复制失败会阻止启动，但不是整个 `Bin` 的原子回滚。修复失败原因后可重新安装同一份已验证产物。启动成功仍需截图与交互验证，不能当作运行验收。

`fstudio_simulator_capture` 只截图，不发送导航、按压或测试值。模拟页面由用户人工操作，或由当前环境另行提供且已获授权的桌面工具操作；设计器切页不能代替模拟器内的导航。操作完成不代表新页面或按下态已经绘制：等待模拟器刷新后截图，逐张核对页标题、目标控件和状态；必要时再次只读截图，不重复按压来追求亮态。不能把上一页截图命名为下一页，也不能把松开后的画面作为按下态证据。

结束时先用当前schema提供的 `fstudio_simulator_close` 请求关闭本次拥有的模拟窗口，核实进程退出。`fstudio_simulator_helper_close` 只关闭该宿主实际创建并持有的FCS辅助进程；原生GUI入口或其他启动方式不保证留下这个归属记录，返回没有拥有的helper时不能当作所有辅助进程已退出。关闭请求与实际退出是不同状态。工具不接管外部进程；宿主重启后丢失归属的旧进程应核实可执行文件、完整离线参数及来源后单独处理，不按名称批量终止。不存在这些工具时，按现有原生模拟入口执行，并明确其可能需要人工处理对话框。

## 活动画布协作与清理

同一宿主只有一个活动工程/画布上下文。切页、草稿配置、提交、释放、保存和重开不能由多个客户端交错执行；只读元数据或离线文件分析可独立进行。开始原生操作前协调一个操作者连续完成，其他任务不要在这期间切页。

草稿用 `try/finally` 清理，并记录ID和创建页。若释放因页面已切换而失败，报告该ID和原页，协调回原页再释放；不通过关闭未保存工程、重建第二个草稿或绕过作用域检查解决。已提交控件与未提交草稿是不同资源，不能用discard删除已经提交的控件。

## 原生语义问题

地址身份、符号、范围、小数缩放、限值子对象、动态扇形图和PNG开关按 [fstudio-native.md](fstudio-native.md) 的版本边界排查。只采用当前schema已暴露且验证过的调用；需要新初始化能力时明确缺口，不把计划中的工具名写成现有可调用接口。最后按 [acceptance.md](acceptance.md) 区分已保存、已编译、已模拟和已联机。
