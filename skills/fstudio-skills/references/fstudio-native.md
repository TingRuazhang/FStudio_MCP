# FStudio 原生实现与排障

## 能力发现和执行生命周期

以当前工具 schema 和原生模型为准。不要把旧会话接口数量、控件数量或某型号测试结果推广为所有版本支持。

常见流程：连接宿主 → 打开工程 → 创建控件草稿 → 读取模型能力 → 设置有关联的属性 → 提交 → 保存 → 关闭重开回读 → 编译 → 运行检查。当前工具若提供 prepare/commit/discard，未完成草稿应明确处理。

返回 job_id 表示排队，轮询同一任务到终态；不要因没有立即看到变化而重复创建。批次写入前确认对象和字段，编译前确认保存。隔离编译通常使用磁盘快照，编辑器未保存的改动不会自动进入该快照。

重开工程后重新获取对象引用。引用失效或宿主管道失效时，先确认进程、插件加载、工作区和连接状态；普通方式打开 FStudio 不一定加载 MCP 宿主插件。不要为此反复改工程内容。

需要 UI 时使用宿主允许的桌面操作工具。每次实际操作后观察结果，不能使用过时窗口句柄或坐标。仅运行模拟器可执行文件可能只有空白窗口；优先使用 FStudio 自带离线模拟入口，确认工程被加载。

## 控件配置的依赖

数值显示与数值输入可能共享一个原生工具类，但模式不同。先显式选 Display/Input，再配置类型、地址、格式、键盘和限值。不要把同名字段的存在当成其已生效。

共用读写地址的控件可能不需要独立 WriteAddress。先读取是否独立读写的开关，再访问对应对象。需独立写地址时通过已支持的原生克隆/创建方法生成，避免直接解引用空 Raw。

显示类型、底层寄存器类型、字宽与字符长度各有含义，需一起核对。限值还要验证越界输入、取消和重开后的值；键盘配置正确不能替代实际点按验证。

地址清单至少包括：工程设备 ID、站号、寄存器区域、地址基准、长度、类型、缩放与读写权限。不同工程的设备 ID 不可照搬；Modbus 零基偏移与 4X 标签差一位的问题应通过实际映射核验。

## 地址身份与不同模型

先识别当前对象是旧式 `AddressInfo`，还是带 `Raw` 的新式 `AddressData`。DTO/catalog 给出的是序列化定义；编辑器公开 getter、集合和可调用工厂应以当前对象的 `model_inspect` / `model_get` 为准。不能把 XML 标签直接当模型属性路径，也不能因两个模型都叫 `RegisterId` 就复用同一个整数转换。

在已核实的 3.0.15685.0 安装中，旧式 `AddressInfo.RegisterId` 为组合编号；新式 `AddressData.Raw.RegisterId` 为 `RegisterIdentity`。原生地址构造路径是驱动寄存器编号与字宽经 `AddressHelper.CombineRegisterId` 合成，再构造保留组合编号的身份。以标准 4X Word 为例，驱动编号4、Word宽度1合成为65540；新式构造须保留 `Id=65540 / Word`。直接使用 `FromCombinedRegisterId(65540)` 的拆分结果会得到 `Id=4 / Word`，本安装曾出现属性回读成功、编译却报“设备寄存器失效”的情况。

这是具体版本的构造约定，不是所有SDK的固定写法。其他安装先对照该版本原生工厂、手工创建样本、保存重开及编译结果；仅凭 `IsValid=true`、显示缩写或工厂名称不能认定身份有效。不要修改装箱结构体的临时副本；应通过已支持的原生入口给属性整体赋值。缺少对应入口时报告能力缺口，不通过猜测 XML 修补身份。

位灯读取4X字内位时，还需核对寄存器区域、字内位开关和位号；`AddressType=Bit` 本身不等于线圈区。固定站号和变量站号也要分开检查，不能让端口默认站号代替所有控件的实际站号。

## 数值类型、精度与缩放

有符号类型先于上下限初始化。16位有符号数据的合法范围是 -32768..32767；生产端即使存入 `uint16_t`，负值也可能按补码传输。核对控件实际使用的读取/显示类型，不能只看变量声明或 Modbus 的16位字宽。

新式数值控件的顶层 `ReadAddress.DataType` 与 `Raw.DataType` 可分别保存显示解释和底层通信类型；有些配置以 UInt16 原始字读取、再由 Int16 解释显示。旧式图表可能只有一个 `AddressInfo.DataType`。逐层回读并用负原始值验证，不把所有层强制设成同一类型。

明确原始值到工程单位的总倍率、偏移、显示小数位与符号策略。`IntegerValue`、正号开关、字体和容器须能容纳负号及最大值；是否显示正号由用户需求决定。带符号数据类型并不要求正数显示“+”。

不要预设 `DecimalValue` 只改变格式。在3.0.15685.0的数值配置中，曾实测仅改小数位就改变原始值的显示比例；与 Zoom/gain 同时使用可能产生重复缩放。先用可计算的原始值隔离测试小数位、运算倍率和 `IsDecimalScaling`，再组合。运算父节点与子节点的两个启用开关可能只是同一运算的门控，不代表执行两次；同名的旧/新属性也可能是别名，按真实模型判断。

圆环或趋势可以直接按原始量程显示比例，旁边数字另做单位转换；两者只要在同一原始值下比例一致，就不必都绑定到已缩放的中间地址。交付记录分别写原始范围、工程范围和最终显示精度。

### 3.0.15685.0 的限值子对象特例

本版本曾出现 `NumericLimit.UseLimit=false` 在原生构造或保存时省略 `MinLimit/MaxLimit` 子对象，重开后编译器访问空对象而异常。不能仅把布尔改成true：需由该版本支持的完整原生DTO/工厂同时初始化最小值、最大值及其常量/变量类型，并关闭任务不需要的溢出替换、颜色和闪烁。

已验证的修复是在选定数据类型后构造完整限值模型，保留 `UseLimit=true`，再保存重开和编译。这是版本故障的针对性处理，不要求所有FStudio工程都开启限值。其他版本先复现并核对原生样本；正常支持关闭限值时沿用任务要求。数值显示的范围、输入校验范围和缩放前后范围需按实际编译/运行语义区分。

## 动态弧长与普通图元

先区分功能相似的原生控件：

| 控件 | 已核实的用途 | 配置重点 |
| --- | --- | --- |
| `SectorRingTool` 图元 | 起止角与内外环比例为常量；动态图形通常控制整体位置、尺寸、旋转 | 不能把整体旋转当成读取值驱动的弧长 |
| `BarTool` 的 `Sector` 形状 | 原生扇形进度图，按读取值及量程改变填充弧长 | `Generic` 的读取地址、最小/最大值、标准/偏差型、原点和方向 |
| `MeterTool` 仪表 | 指针和范围标尺；另有滑动写入模式 | 选择只读显示用途，不把 `MeterDisplay` 当成进度环形状枚举 |

这些接口已在3.0.15685.0发现并做过草稿回读；其他版本重新确认工具和模型。`Bar` 当前的量程成员拼写为 `Minimun` / `Maximun`，常量包装对象与地址对象不要混用；`Generic.Angle.Scale` 是内外半径百分比，不能当作数值倍率。有些形状参数在 `Generic` 与 `Extensional` 各保存一份，应核对原生同步方式和最终两侧值。

负数的数字符号、偏差型原点、填充方向和颜色是不同需求。仅在用户需要时区分正负颜色，不把负值自动解释为故障。若借用上下界着色，本版本要求下界严格小于上界；同设零会使扩展子节点无效，根 `BrokenRulesCollection` 却可能为空。检查子节点规则，不因根规则为空就认为控件有效。颜色、透明背景和负值弧长均须实际运行验证。

## PNG透明与独立通信配置

PNG文件具有alpha通道不等于原生控件会使用它。当前图片模型需要核对 `NormalInfo.AlphaColor.IsUsePngAlphaChannel`；导入、复制或重开后再次回读。透明颜色选择、PNG alpha开关和“无背景填充”是不同机制，须结合实际合成截图检查，避免矩形底色遮盖公共层或旧轨道。

通信配置可能单独保存在 `HMIInfo`，画布的项目保存入口不一定写入它。在已核实版本中，修改原生端口后还需使用暴露的 `HMIInfo.SaveToFile` 写入其实际配置文件，再正常保存、重开并回读。文件路径从工程和原生配置取得；不能固定到另一工程。核对驱动、主从角色、串口参数、站号和地址基准，并用编译结果检查地址身份。其他版本以实际保存机制为准。

## 原生文件修改

优先使用受支持的原生 API。必须离线修改 XML 时：

1. 确认目标工程关闭或已在隔离副本中；保留备份，避免磁盘改动被编辑器旧模型覆盖。
2. 采用当前版本原生保存的最小模板；保留命名空间、字段顺序、枚举和值类型。看起来相同的字符串不保证反序列化语义相同。
3. 区分控件身份与外部资源引用。控件唯一身份应唯一；图库、设备、语言资源等合法共享引用不能盲目重建，也不能因为相同就认定冲突。
4. 按稳定注释/业务标识查找唯一对象，缺失或重名则停止该修改。版本变化时先重新发现模型。
5. 原子保存后原生重开，读取最终属性再编译；XML 可解析只是最低限度检查。

不要绕过原生不支持的控件或保留页保护。支持声明需要包含具体配置和证据层级。若有替代实现，保持功能语义，并说明差异。

## 已观察的陷阱及证据边界

以下来自 FStudio 3.0.15685.0、F010 的开发记录。用于指导复现，不能视为所有版本的确定规则。

| 观察 | 当时确认的原因或边界 | 可迁移做法 |
| --- | --- | --- |
| 数字右侧单位被数字挤到左边 | 数值控件重开后将设定的 90 宽重新扩到 121，而单位未移动 | 依据最终尺寸分配数字与单位空间，勿把 121 当所有控件常量 |
| 子页透明但模拟背景黑 | 公共窗口背景属性未呈现预期底色；公共底层矩形在离线模拟中生效 | 对比公共属性与图元机制，并验证跨页层级和点击 |
| 单独启动 FSGUI 只有白窗 | 进程存在没有证明工程运行环境已加载 | 从工程的原生离线入口启动，实际查看内容 |
| 字体和文字观感与原型不符 | 曾调整字号、字体和边界，但没有单一根因对照试验证明“小数字号必然缺字” | 排查候选原因，每次只改变可解释的因素 |
| 文本库 ID 相同 | 合法系统资源也可能共享 ID | 不能只靠 ID 相同断言文字串扰 |
| 控件创建和保存成功但固件能力缺失 | 部分控件或可选模式不被原生编译器支持；历史数据显示某些搜索模式未输出 | 检查目标产物的字段，而非只检查成功返回 |
| 原生环形控件可运行但风格仍不像原型 | 动态功能与刻度、内圈、字重等视觉细节是独立验收项 | 原生功能保留，逐项补齐支持的视觉细节；不声称已达到 1:1 |

## 最小复现策略

先确认失败层：请求校验、异步执行、模型配置、保存重开、编译、运行、硬件。保留错误、对应对象、版本和相关配置，逐项缩减到一个控件。

对比“原生手工创建可运行样本”和“生成样本”的关键字段；不要随机枚举属性和值。被明确拒绝的能力若无新版本或新证据，不重复尝试相同参数。

修改一个根因后，重开相关对象并运行对应检查。涉及公共页面时扩大到受影响页面；涉及地址和类型时扩大到读写边界。避免因为修一个单位对齐而无目的重测全部平台接口。
